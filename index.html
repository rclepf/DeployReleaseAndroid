00_contexto.md

Build de Debug vs. Build de Release

Toda vez que vocês clicaram em ▶ Run no Android Studio ao longo do ano, o Android Studio gerou um build de debug: um APK assinado automaticamente com uma chave genérica (a debug keystore), que o próprio Android Studio cria e gerencia sem perguntar nada. Ela existe só para permitir testes rápidos no emulador ou no celular conectado por cabo — e, por isso, o Android recusa instalar esse tipo de build fora de um ambiente de desenvolvimento.

Um build de release é diferente: é o pacote final, otimizado e assinado com uma chave que vocês criam e controlam — a mesma chave que vai identificar o app para sempre, inclusive em futuras atualizações. É esse tipo de build que se instala "de verdade" num celular, fora do Android Studio, e é o único tipo aceito pela Google Play Store.

01_assinatura.md

Assinatura Digital: a Identidade do seu App

Toda chave de release é um arquivo keystore (extensão .jks ou .keystore) — um certificado digital que funciona como a "impressão digital" permanente do seu app. O Android usa essa assinatura para duas garantias importantes:

  • Autenticidade: provar que uma atualização do app realmente veio de quem publicou a versão original (e não de alguém se passando por vocês).
  • Continuidade: permitir que o sistema reconheça uma nova versão como "a mesma app", preservando dados do usuário (como preferências salvas) entre atualizações.
Por que isso é sério: se vocês perderem a keystore de um app publicado, não existe forma de recuperá-la — nem a própria Google consegue restaurar. A única opção seria publicar o app como um produto totalmente novo, perdendo todo o histórico de instalações e avaliações. É por isso que, no mercado, a keystore de um app em produção é tratada como uma credencial crítica: guardada em cofre de senhas da empresa, nunca enviada por e-mail ou commitada no Git.
02_build.md

Passo a Passo: Gerando um APK Assinado

Passo 1 — Abrir o assistente de build 1/5

No menu superior do Android Studio: Build → Generate Signed Bundle / APK...

Passo 2 — Escolher o formato 2/5

Selecione APK (não Android App Bundle). O AAB é o formato que a Play Store exige para publicação — mas para instalar diretamente no seu celular, sem passar pela loja, o APK é o caminho direto. Clique em Next.

Passo 3 — Criar a keystore 3/5

Clique em Create new.... Preencha:

  • Key store path: onde salvar o arquivo .jks (escolham uma pasta fora do projeto — ela não deve ir para o Git).
  • Password: uma senha para o arquivo da keystore.
  • Alias e Password da chave em si (pode repetir a mesma senha).
  • Validity (years): deixe pelo menos 25 — a Google recomenda validade além de 2033.
  • Dados do certificado (nome, organização): podem ser fictícios para fins de aula, mas preenchidos.
Anote a senha agora: sem ela, vocês não conseguem gerar uma nova versão assinada com a mesma identidade depois.

Passo 4 — Escolher a variante 4/5

Marque release (não debug). Se aparecerem checkboxes de V1 e V2 (Signature Versions), deixe ambas marcadas — são dois esquemas de verificação de assinatura, e manter os dois garante compatibilidade com versões mais antigas do Android.

Passo 5 — Localizar o APK gerado 5/5

Ao final, o Android Studio mostra uma notificação com um link locate. O arquivo fica em app/release/app-release.apk dentro da pasta do projeto.

03_instalacao.md

Instalando no Próprio Celular

Transfiram o arquivo app-release.apk para o celular (cabo USB, Google Drive, ou qualquer forma de transferência) e toquem nele pelo gerenciador de arquivos do Android para instalar.

Google Play Protect vai alertar — e está certo em fazer isso. Como o app não veio da Play Store, o Android mostra um aviso de segurança antes de instalar. É o comportamento esperado para qualquer APK instalado "por fora" (chamado de sideloading); confirmem a instalação mesmo assim, já que é o próprio app de vocês.
04_play_console.md

Visão Geral do Google Play Console

Não vamos publicar nenhum app na Play Store nesta etapa — mas vale conhecer o caminho que um app percorre depois do APK/AAB assinado, porque é o destino natural de qualquer projeto real:

  1. Criar uma conta de desenvolvedor no Google Play Console (taxa única de cadastro).
  2. Criar uma nova "aplicação" e preencher a ficha da loja (nome, descrição, capturas de tela, ícone, política de privacidade).
  3. Fazer upload do .aab (não do .apk — a Play Store exige o Bundle, que ela mesma converte em APKs otimizados por tipo de dispositivo).
  4. Passar pela revisão de conteúdo e políticas da Google antes de ficar público.
99_erros_comuns.md

Erros Comuns

App not installed as package conflicts with an existing package

Causa: já existe, no celular, uma versão de debug do mesmo app instalada (via ▶ Run) — e ela foi assinada com uma chave diferente da keystore de release.

Solução: desinstalem a versão de debug do celular antes de instalar o APK de release. O Android não permite duas versões do mesmo pacote com assinaturas diferentes coexistindo.

O app instala e roda no emulador (debug), mas trava ao abrir na versão release

Causa: o R8 (o otimizador/ofuscador que só roda no build de release) removeu ou renomeou classes que o Gson/Retrofit precisa encontrar pelo nome exato para converter o JSON — geralmente as data class do modelo.

Solução: adicionem regras de manutenção no arquivo proguard-rules.pro para as classes de modelo, por exemplo -keep class com.rclepf.pokedexnovo.data.** { *; }, substituindo pelo pacote de dados do projeto de vocês.

Esqueci a senha da keystore

Causa: não há recuperação — é assim por design, para que ninguém além de quem tem a senha consiga gerar uma versão "autêntica" do app.

Solução para esta disciplina: gerem uma nova keystore e um novo build — para fins de avaliação, não há histórico de usuários reais em jogo. Anotem a senha desta vez num lugar seguro.

A opção "Android App Bundle" está cinza/desabilitada no assistente

Causa: normalmente não é um erro — é só a seleção padrão já estar em "APK", que é o formato certo para o que esta aula pede (instalação direta no celular).

Solução: nenhuma ação necessária; sigam com APK. O AAB só é obrigatório no momento de publicar na Play Store de verdade.
